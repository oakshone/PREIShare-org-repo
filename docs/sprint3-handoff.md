# Sprint 3 Handoff: PREIshare Investor Dashboard Shell

**Audience:** PREIshare stakeholders, the next sprint's topic owners, and course reviewers  
**Status:** Dashboard shell complete with labelled mock data; no live data, auth, or payments  
**Date:** 2026-10-10  
**Prepared by:** Jackson Nieporte  
**Source brief:** `docs/investor-dashboard-brief.md`  
**Build:** `main` @ `628fe42` (includes the Home sample-data update, QA cycle 5)

## 1. Summary for stakeholders

- Investors now have a dashboard at `/dashboard` with four areas: **Home**, **Portfolio**, **Deals**, and **Profile**. They all sit in one consistent frame: a header, navigation, and a main content area.
- It works on phones, tablets, and desktops. On desktop there's a sidebar. Below 1024px a "Menu" button shows the same four links.
- **Every number, name, and deal on screen is sample data,** and each page says so: the header reads "Not signed in · sample data", and every widget carries a "Sample" note. The sample figures agree from page to page, so the demo feels like one investor's account.
- All six success criteria in the brief are met (section 2.1). The verification checklist records **41 Pass, 1 Fail, and 14 Deferred** (8 of them out of scope by design). The one Fail is a small keyboard-order issue caused by the starter site's header (section 5).

**What to say in a demo:** "This is the investor dashboard shell with sample data. Live accounts, sign-in, and investing come in later sprints."

## 3. How to run locally

Requires **Node 22.12 or newer** (TanStack Start's minimum).

```bash
npm install
npm run dev          # http://localhost:3000/dashboard
```

To check what Vercel will build:

```bash
npm run typecheck    # TypeScript, no errors expected
npm run build        # production build
npm run preview      # serves the build (default http://localhost:4173/dashboard)
```

No `.env` values are needed: the dashboard uses built-in sample data only.

## 4. Demo script (about 5 minutes)

Open `/dashboard` on a desktop-width window (1024px or wider).

1. **Frame (30s):** point out the header (PREIshare, page title "Home overview", "Demo investor · Not signed in · sample data") and the sidebar with Home highlighted.
2. **Home (60s):**
   - Read the banner "Demo shell — sample figures only, no live data is connected yet".
   - Walk the metric cards: $300,000 portfolio value, 2 active investments (1 pending), $6,400 distributions year to date.
   - Show the portfolio summary (three holdings, 40 / 35 / 25%) and recent activity (a $3,200 distribution, a capital call, an investor update).
3. **Portfolio (45s):** click Portfolio in the sidebar. The title changes, and the same three holdings appear with invested amount, current value, and status. Point out that these figures match Home.
4. **Deals (45s):** click Deals. Show three sample offerings with Open, Closing soon, and Waitlist badges. Note that there's no invest button on purpose: investing is out of scope this sprint.
5. **Profile (30s):** click Profile. Show the read-only card: "Demo investor", accredited investor, `example.com` email.
6. **Phone view (60s):** narrow the window, or use device emulation at 375px. The sidebar is replaced by a "Menu" button. Tap it, choose Deals, and show that the menu closes and the cards stack.
7. **Close (30s):** "Everything you saw is sample data. Next sprint connects real accounts and sign-in."

## 5. Known limitations

**Mock data**
- **Every figure is sample data,** built into the components or the Home page: metrics, holdings, activity, deals, and profile. None of it comes from Supabase/PostgreSQL.
- **Sample totals are written in by hand,** for example Home's $300,000. They are consistent today, but they won't update if someone edits a single sample row.
- **Very large values aren't tested.** A value like "$12,345,678,901" wraps mid-number in a metric card. Today's sample values fit on one line.

**Not built (by design, per the brief)**
- **Sign-in:** anyone can open `/dashboard`, and the member shown is a placeholder. `src/lib/user.ts` `getUser()` returns `null`.
- **Saving changes:** no saving, editing, or forms.
- **Investing:** no payments, subscriptions, checkout, or e-sign.
- **Admin:** no admin tools.
- **Production hardening:** none yet (monitoring, error pages, CI).

**Open issues from verification**
- **Fail (A7):** the starter site header and footer from the project template still wrap the dashboard. That makes "Skip to content" the 6th keyboard stop instead of the 1st.
- **Not yet tried with the system settings turned on:** reduced motion and high-contrast mode. The rules are written in `dashboard.css`.
- **Not tested with a screen reader or on a real phone or tablet.**
- **Live Vercel deploy:** not confirmed from here after the security fix. Check the Vercel dashboard. The project must use Node 22.12+.
- **Sidebar isn't sticky on desktop.** That's fine for these short pages.

## 6. Recommended next-sprint work

1. **Real data, read-only first.**
   - Add loaders on each page (not the shared layout) and server functions for anything secret, reading from Supabase/PostgreSQL.
   - Feed the existing components through their typed props (`HoldingSnapshot`, `ActivityItem`, `PortfolioHolding`, `Deal`, `InvestorProfile`) and keep the components as they are.
   - Calculate totals like portfolio value from the rows instead of writing them in.
2. **Sign-in.** Add authentication, protect `/dashboard` for signed-in investors, and replace the "Demo investor" placeholder with the real member. Turn off the sample notes (`isSampleData={false}`) only where real data is shown.
3. **Remove the starter header and footer from dashboard pages** (`src/routes/__root.tsx`). This fixes A7, then re-test keyboard order.
4. **Re-run verification with real content:**
   - long names, large values, and empty lists
   - reduced-motion and high-contrast modes
   - a screen reader and one real phone
5. **Confirm the Vercel deploy** and set the Node version. Optionally add `"engines": { "node": ">=22.12.0" }` to `package.json`.
6. **Later, with product sign-off:** investing/checkout flows, profile editing, and admin tools. All are out of scope in the current brief.
